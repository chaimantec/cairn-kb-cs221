## Section: UCS — Motivation (`ucs_motivation`)

**Two key concepts in search:**
- **Future cost**: minimum cost solution from `state` to an end state.
- **Past cost**: minimum cost solution from the start state to `state`.

(Diagram: `past-future.png` — a horizontal chain of four light-gray rounded rectangles labeled start, state, state′ and end, connected by plain right-pointing arrows, with ellipses between start and state and between state′ and end. Above the chain, curly-bracket spans from start to state′ and from state′ to end are labeled PastCost(state′) and FutureCost(state′); below it, matching spans are labeled PastCost(state) and FutureCost(state). No numeric cost values are printed.)

In dynamic programming, we compute the future cost for each state.
Note `future_cost(state)` depends on `future_cost(state')` and thus must be computed after it.
So FutureCost(state) are computed from the end states to the start state (like in backpropagation).
Assumption: there are no cycles.

**Now suppose that there are cycles (special case: undirected edges).**

(Diagram: `diamond-example.png` — four black-outlined white circles labeled A, B, C, D forming a diamond (A left, B top, C bottom, D right), connected by five plain black lines drawn without arrowheads; each line carries a single red cost label: A–B "1", A–C "100", B–C "1", B–D "100", C–D "1". Caption: "Start state: A, end state: D".)

Which do we compute first, B or C?
In general, in what order do we process the states?

**Uniform Cost Search (UCS)** [Dijkstra, 1956]
Assumption: all costs are non-negative.
Two differences from dynamic programming:
- Compute **past costs** for each state (instead of future costs).
- Process states **in order of increasing past cost** (instead of topological order).

**High-level strategy:**

(Diagram: `ucs-strategy.png` — two concentric ellipses: a smaller light-green inner ellipse labeled "Explored", a larger light-peach outer ellipse labeled "Frontier", and the white region outside both labeled "Unexplored". No arrows or other marks.)

- **Explored**: states we've found the minimum cost path to
- **Frontier**: states we've seen, still trying to figure out how the best way to get there
- **Unexplored**: states we haven't seen yet

## Section: UCS — The Algorithm (`uniform_cost_search`)

### The Backpointer (`Backpointer`)

For a state, record how we got to it.

```python
@dataclass(frozen=True)
class Backpointer:
    """For a state, record how we got to it."""
    prev_state: Any   # Which state we came from
    action: Any       # Action we took from `prev_state`
    cost: float       # Cost of that action
```

### Uniform Cost Search

```python
def uniform_cost_search(problem: SearchProblem) -> tuple[Solution | None, int]:
    """
    Run Uniform Cost Search (UCS) on the specified search `problem`.
    Return the solution (sequence of steps) and the number of states explored.
    """
    # Frontier: states we've seen, still trying to figure out how the best way to get there
    # Priority represents the minimum cost to get there
    frontier = PriorityQueue()

    # For each state we've reached, backpointer tells us how we got there
    backpointers: dict[Any, Backpointer] = {}
    num_explored = 0

    # Add the start state
    start_state = problem.start_state()
    frontier.update(start_state, 0.0)

    while True:
        # Remove the state from the frontier with the lowest priority (theorem: priority = past_cost).
        state, past_cost = frontier.remove_min()
        if state is None and past_cost is None:
            return None, num_explored  # Found no solution

        num_explored += 1

        # Check if we've reached an end state; if so, extract solution.
        if problem.is_end(state):
            # Walk back the backpointers to get the actions
            steps = []
            while state != start_state:
                backpointer = backpointers[state]
                steps.insert(0, Step(backpointer.action, backpointer.cost, state))  # Prepend
                state = backpointer.prev_state  # Go back
            return Solution(steps=steps), num_explored

        # Expand from `state`, updating the frontier with each `new_state`
        for successor in problem.successors(state):
            if frontier.update(successor.state, past_cost + successor.cost):
                # We found better way to get to `successor.state` --> update backpointer!
                backpointers[successor.state] = Backpointer(prev_state=state, action=successor.action, cost=successor.cost)
```

### The Priority Queue

```python
class PriorityQueue:
    """Data structure for supporting uniform cost search."""
    def __init__(self):
        self.DONE = -100000
        self.heap = []
        self.priorities = {}  # Map from state to priority

    def update(self, state: Any, new_priority: float) -> bool:
        """
        Insert `state` into the heap with priority `new_priority` if `state`
        isn't in the heap or `new_priority` is smaller than the existing
        priority.  Return whether the priority queue was updated.
        """
        old_priority = self.priorities.get(state)
        if old_priority is None or new_priority < old_priority:
            self.priorities[state] = new_priority
            heapq.heappush(self.heap, (new_priority, state))
            return True
        return False

    def remove_min(self):
        """Return (state with minimum priority, priority) or (None, None) if empty."""
        while len(self.heap) > 0:
            priority, state = heapq.heappop(self.heap)
            if self.priorities[state] == self.DONE:
                # Outdated priority, skip
                continue
            self.priorities[state] = self.DONE
            return state, priority

        # Nothing left...
        return None, None

    def asdict(self) -> dict[Any, float]:
        """Return the priorities without the DONE ones."""
        return dict((state, priority) for state, priority in self.priorities.items() if priority != self.DONE)
```

Stale heap entries are skipped via the `DONE` marker rather than removed: `update` can push a state twice, and the outdated entry is discarded when it reaches the top of the heap.

class DiamondSearchProblem(SearchProblem):
    def __init__(self):
        # state -> state -> cost
        self.graph = {
            "A": {"B": 1, "C": 100},
            "B": {"A": 1, "C": 1, "D": 100},

### The Grid Problem (`GridSearchProblem`)

Let's consider another search problem:
- States are points on a grid (start at S, end at E)
- Actions: up, down, left, right
- Cost: 1 for each action

```python
class GridSearchProblem(SearchProblem):
    def __init__(self, *rows: list[str]):
        # Remove spaces (which are just for readability)
        self.rows = [row.replace(" ", "") for row in rows]

    def start_state(self) -> str:
        for r in range(self.num_rows):
            for c in range(self.num_cols):
                if self.rows[r][c] == "S":
                    return (r, c)
        raise ValueError("No start state found")

    def is_valid(self, state: tuple[int, int]) -> bool:
        """Check if a state is valid."""
        r, c = state
        return 0 <= r < self.num_rows and \
               0 <= c < self.num_cols and \
               self.rows[r][c] != "#"

    def successors(self, state: tuple[int, int]) -> list[Step]:
        """Return the successors of a state (up, down, left, right)."""
        r, c = state
        successors = []
        if self.is_valid((r + 1, c)):
            successors.append(Step(action="down", cost=1, state=(r + 1, c)))
        if self.is_valid((r - 1, c)):
            successors.append(Step(action="up", cost=1, state=(r - 1, c)))
        if self.is_valid((r, c + 1)):
            successors.append(Step(action="right", cost=1, state=(r, c + 1)))
        if self.is_valid((r, c - 1)):
            successors.append(Step(action="left", cost=1, state=(r, c - 1)))
        return successors

    def is_end(self, state: tuple[int, int]) -> bool:
        """Check if a state is an end state."""
        r, c = state
        return self.rows[r][c] == "E"
```

## Section: UCS — Correctness (`ucs_correctness`)

We now prove that UCS is guaranteed to compute the minimum cost solution.
Assumption: all costs are non-negative.

(Diagram: `ucs-strategy.png` — two concentric ellipses: a smaller light-green inner ellipse labeled "Explored", a larger light-peach outer ellipse labeled "Frontier", and the white region outside both labeled "Unexplored". No arrows or other marks.)

**Theorem:**
- Suppose UCS moves a state s from the frontier to the explored set.
- Then priority(s) = PastCost(s).

Let's prove by induction.
Base case: priority(start) = PastCost(start) = 0.

(Diagram: `ucs-proof.png` — a large green ellipse labeled "Explored". Inside it, a black dot labeled s_start is the origin of two paths to a black dot labeled s that sits just outside the ellipse's right edge. The blue path is a single straight blue arrow from s_start to s. The red path runs from s_start via a red arrow to a black dot labeled t on the ellipse's boundary, then a plain red line segment (no arrowhead) to a black dot labeled u just outside the boundary, then a red arrow up to s. No numeric cost labels appear; segments are distinguished only by color.)

Inductive case: assume priority(s) = PastCost(s) for all s in explored.
- Suppose we remove s from the frontier, corresponding to blue path.
- Consider any alternative red path to s that goes through t (in explored) and u (in frontier).
- Want to show cost(red) ≥ cost(blue).

```
cost(red)
≥ PastCost(t) + Cost(t, u)   [PastCost(t) is minimum cost to t, u to s is non-negative]
= priority(t) + Cost(t, u)   [inductive hypothesis]
≥ priority(u)                [t is explored, used to update priority(u)]
≥ priority(s)                [s has minimum priority from frontier]
= cost(blue)                 [by definition]
```

## Section: A* (`astar`)

- UCS in action: [UCS video](https://www.youtube.com/watch?v=z6lUnb9ktkE)
- A* in action: [A* video](https://www.youtube.com/watch?v=huJEgJ82360)

UCS orders states by increasing past cost (which has no knowledge of the end state).
We would also like to consider the cost from state to an end state.
Ideal: explore in order of PastCost(s) + FutureCost(s)
A*: explore in order of PastCost(s) + h(s) for some **heuristic** h(s)
h(s) is an approximation of FutureCost(s)

**A* algorithm** [Hart/Nilsson/Raphael 1968]: run UCS with modified costs:

```
Cost'(s, a) = Cost(s, a) + [h(Succ(s, a)) - h(s)]
```

Intuition: add a penalty for how much action takes us away from the end state

### The Line Example (`LineSearchProblem`)

Let's consider a simple example:

```python
class LineSearchProblem(SearchProblem):
    def start_state(self) -> int:
        return 0

    def successors(self, state: int) -> list[Step]:
        successors = []
        if state >= -2:
            successors.append(Step(action="left", cost=1, state=state - 1))
        if state <= 2:
            successors.append(Step(action="right", cost=1, state=state + 1))
        return successors

    def is_end(self, state: int) -> bool:
        return state == 2
```

(Graph: `var/line_graph.png`, rendered by `draw_graph` — five circle nodes labeled -2, -1, 0, 1, 2 in a chain, with 2 drawn as a double circle (the end state); each adjacent pair connected by two directed edges labeled `left:1` and `right:1`.)

At the start: `start_state()` = 0; successors = [left → -1 (cost 1), right → 1 (cost 1)]; `is_end(1)` = False.

**Let's run UCS on this example.**
Solution: right (1), right (1) — two steps from 0 to 2, total cost 2. **5 states explored** (UCS explores -1 and -2 on the way because it has no sense of the end state).

**Let's run A* on this example.**

```python
def line_heuristic(state: int) -> float:
    return 2 - state
```

Heuristic values: h(2) = 0, h(0) = 2, h(-2) = 4. (h(s) = distance from s to the end state 2.)

The modified problem for state 0: successors become left → -1 with modified cost 1 + h(-1) − h(0) = 1 + 3 − 2 = **2**, and right → 1 with modified cost 1 + h(1) − h(0) = 1 + 1 − 2 = **0**.

Note that the heuristic makes us favor going to the right.

A* solution: right (modified cost 0), right (modified cost 0) — modified solution cost 0, **3 states explored**. The costs are then restored to the originals (each modified cost = original + h(new) − h(old), inverted): right (1), right (1), total cost 2.

Will any heuristic work?

No.

Here, h(C) = 1000 actively messes things up.

### Consistency

**Consistency**: a heuristic h is consistent when
- Cost(s, a) + h(Succ(s, a)) - h(s) is non-negative (these are the modified costs!).
- h(end) = 0.

UCS does not work with negative costs.

### Correctness Proposition

Proposition (correctness): A* is correct if h is consistent.
Proof:
- Consider any path from the start state to the end state.
- The sum of the modified costs is the sum of the original costs - h(start).
- Reason: telescoping sums

### Efficiency Proposition

Proposition (efficiency): A* explores all states satisfying

```
PastCost(s) <= PastCost(end) - h(s)
```

Proof: A* explores all s such that PastCost(s) + h(s) <= PastCost(end)
- If h(s) = 0, then A* = UCS.
- If h(s) = FutureCost(s), then A* explores only nodes on minimum cost path.
- Usually h(s) is somewhere in between.

### Admissibility

Definition (admissibility): h is admissible when h(s) <= FutureCost(s)
In other words: h always underestimates the cost
Consistency implies admissibility.

### How `astar_search` Works

```python
def astar_search(problem: SearchProblem, heuristic: Heuristic) -> tuple[Solution | None, int]:
    """Just wrap the problem and return the solution."""
    modified_problem = ModifiedSearchProblem(problem, heuristic)
    modified_solution, num_explored = uniform_cost_search(modified_problem)

    # The actions are correct but the costs are still the modified costs!
    # Need to get the original costs from the modified solution.
    state = problem.start_state()
    steps = []
    for step in modified_solution.steps:  # step: state ----> step.state
        modified_cost = step.cost
        # Recall: modified_cost = original_cost + heuristic(step.state) - heuristic(state)
        original_cost = modified_cost - heuristic(step.state) + heuristic(state)
        steps.append(Step(step.action, original_cost, step.state))
        state = step.state
    solution = Solution(steps=steps)
    return solution, num_explored


class ModifiedSearchProblem(SearchProblem):
    """A modified search problem where the costs are based on the `heuristic`."""
    def __init__(self, problem: SearchProblem, heuristic: Heuristic):
        self.problem = problem
        self.heuristic = heuristic

    def start_state(self) -> Any:
        return self.problem.start_state()

    def successors(self, state: Any) -> list[Step]:
        """Return the successors of `state`."""
        successors = []
        for successor in self.problem.successors(state):
            # Modify the cost using the heuristic
            modified_cost = successor.cost + self.heuristic(successor.state) - self.heuristic(state)
            successors.append(Step(successor.action, modified_cost, successor.state))
        return successors

    def is_end(self, state: Any) -> bool:
        return self.problem.is_end(state)
```

A* is exactly UCS run on `ModifiedSearchProblem`: the actions are unchanged, only the costs are shifted by the heuristic difference h(Succ(s, a)) − h(s).

## Section: Heuristics via Relaxations (`astar_relaxations`)

So far: A* = UCS with a modified cost based on a heuristic function h
h(s) needs to be consistent for A* to be correct
How do we choose h?

**Key principle: relaxation**
Ideally, h(s) = FutureCost(s), but that's just as hard as solving the original problem.
So let's relax the problem to make it easier.

**Winning recipe:**
- Define a relaxed problem by getting rid of some constraints.
- Compute FutureCost_relaxed(s) to be the future cost of state s under the relaxed problem.
- Run A* using heuristic h(s) = FutureCost_relaxed(s).

Here are some ways in which the relaxed problem is easier.

### Closed-Form Solution (`closed_form_solution`)

Recall the grid problem of going from S to E without going through walls (#).

In the relaxed problem, just remove all the walls! The future cost of a state (r, c) under the relaxed problem has a closed form solution:

```python
def future_cost_relaxed(state: tuple[int, int]) -> float:
    end_r = relaxed_problem.num_rows - 1
    end_c = relaxed_problem.num_cols - 1
    # Manhattan distance between (r, c) and (end_r, end_c)
    r, c = state
    dist = abs(end_r - r) + abs(end_c - c)
    return dist
```

Manhattan distance on the 5×5 grid (end at (4, 4)):

| state | future_cost_relaxed |
| ----- | ------------------- |
| (0, 0) | 8 |
| (0, 1) | 7 — "Closer" |
| (2, 4) | 2 — "Seems so close!" |
| (3, 0) | 5 — "Seems farther (heuristic is imperfect)!" |

Intuition: favor states that are closer to E

Run UCS and A*:
- UCS: solution cost 14, **17 states explored**.
- A* (Manhattan heuristic): same solution cost 14, **17 states explored**.

Note that A* does not provide a benefit in this case.

### Search Fewer States (`search_fewer_states`)

Recall the limited travel problem:
- Travel from 1 to n via walking (i → i+1) or tram (i → 2*i)
- Can take tram only `tickets` times

Original problem: `LimitedTravelSearchProblem(num_locs=10, starting_tickets=3)`.
Relaxed problem: tram is free again! `TravelSearchProblem(num_locs=10)`.

To define the heuristic, we need to compute future costs of the relaxed problem. Dynamic programming on the relaxed problem explores **10 states** (`num_explored_relaxed` = 10). The heuristic maps a problem state (loc, tickets) to the relaxed future cost at loc:

```python
def heuristic(state: TravelState) -> float:
    # Note: problem states are (loc, tickets) but relaxed problem states are just loc
    state_relaxed = state.loc
    return future_costs_relaxed[state_relaxed].cost
```

For example, `heuristic(TravelState(loc=4, tickets=3))` = 3.

Let's compare UCS and A*:
- UCS: solution walk, tram, walk, tram (loc 1 → 2 → 4 → 5 → 10), total cost 6, **23 states explored**.
- A*: same solution, cost 6, **8 states explored**.

For accounting purposes, need to include the cost of solving the relaxed problem: 8 + 10 = **18** states explored in total (A* still wins).

Note: dynamic programming cannot deal with cycles.
If we have cycles, what do we do?
Solution:
- Define a reversed relaxed problem (A → B becomes B → A)
- Past costs in the reversed relaxed problem = future costs in the relaxed problem
- Run UCS on the reversed relaxed problem to compute future costs in the relaxed problem

Summary:
- Still have to run search on the relaxed problems
- But the relaxed problems have fewer constraints and therefore fewer states
- Thus they are faster to solve than the original problem

### Independent Subproblems (`independent_subproblems`)

### The Unifying Principle (`unifying_principle`)

Examples of relaxed problems so far:
- Knock down walls
- Free tram
- Tiles can overlap

These are all examples of removing constraints from the original problem.
Removing constraints means reducing the cost of actions from infinity to a finite value.

A more general principle: **reducing costs**

Definition: A **relaxation** of a search problem is a modified problem where
- States, actions, successors are the same
- Cost_relaxed(s, a) <= Cost(s, a)

Theorem: Let h(s) be the future cost of a relaxed problem. Then h is a consistent heuristic.
Proof:

```
h(s)
<= Cost_relaxed(s, a) + h(Succ(s, a))   [triangle inequality]
<= Cost(s, a) + h(Succ(s, a))           [definition of relaxation]
```

Of course, a relaxed problem isn't automatically easier to solve!

Costs are reduced in a **structured** way so that we can then:
- Reduce the number of states
- Get closed form solutions
- Break up into independent subproblems

### Combining Heuristics (`combining_heuristics`)

We can use domain knowledge to come up with different relaxations
- h1(s): future cost if we knock down walls
- h2(s): future cost if we can ride a free tram

Which one do you pick?
Answer: you don't have to - you can use all of them!

Theorem:
- Suppose h1(s) and h2(s) are two consistent heuristics.
- Then h(s) = max(h1(s), h2(s)) is a consistent heuristic.

Proof:

```
h(s)
= max(h1(s), h2(s))                                                       [definition of h]
<= max(Cost(s, a) + h1(Succ(s, a)), h2(Cost(s, a)) + h2(Succ(s, a)))     [because h1 and h2 are consistent]
= Cost(s, a) + max(h1(Succ(s, a)), h2(Succ(s, a)))                       [pull out constant]
= Cost(s, a) + h(Succ(s, a))                                             [definition of h]
```

Therefore, h is consistent.

## Section: Summary (`main`)

- UCS and A* are two exact algorithms that allow for cycles (but non-negative costs)
- Key: order states by increasing past cost
- Can't do better than UCS in general
- A* allows you to incorporate domain knowledge via heuristics to speed up search
- Heuristics: future cost of some relaxed problem (lowering costs in a structured way)
